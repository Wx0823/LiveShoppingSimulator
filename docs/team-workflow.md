# 美术与测试协作

## 分工

- 主开发：接入交互、保存顺序、桌面展示、版本记录与打包。
- 人物美术：每位武将独立立绘，确认人物、阵营配色、武器与裁切安全区。
- 包装美术：三套阵营包装、卡背、统一卡面框架；协作人物图时明确分配具体文件。
- 测试：独立检查画面和操作，并通过单测、浏览器与真实 Electron 验证接口。审查员独立复核经济和存档代码。

同一个文件同一时间只分配给一位实现者。测试使用隔离 Context 或 `artifacts/` 下测试存档，不能加载玩家真实桌面存档。主开发收到缺陷后修复，测试负责复核，并将结果写入对应版本的 QA 文档。

## 当前验收入口

先启动 `pnpm dev`，再按改动范围运行：

| 命令 | 范围 |
| --- | --- |
| `pnpm test` | 卡池、概率、经济、队列、旧存档、滚动算法 |
| `pnpm test:layout` | 720p、960p、1080p、4K 布局与预览分页 |
| `pnpm test:ui` | 购买、背包、奖励、设置、存档恢复 |
| `pnpm test:live` | 自动拆包、五包队列、阵营同步、玩家排队 |
| `pnpm test:unboxing` | 滚动揭晓、跳过、减弱动态、重载 |
| `pnpm test:cards` | 卡面翻转、概率分页、保存失败、历史藏品 |
| `pnpm test:art` | 51 个实际位图解码、45 张立绘唯一性 |
| `pnpm test:desktop` | Electron 隔离、磁盘保存、IPC、单实例 |

完成素材后还需逐阵营目检卡面总览，避免仅凭文件存在或接口通过判定美术完成。发布包输出到 `dist/v版本号/`；通过 `LSS_TEST_EXE` 指向实际 EXE，再运行桌面测试。不得将开发版测试结果当成最终包验证。

版本号、CHANGELOG、QA 记录与 Git 提交一起交付，通过后添加版本标签。
